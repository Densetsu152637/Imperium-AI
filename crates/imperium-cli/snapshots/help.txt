===== imperium =====
Command-line client for the Imperium daemon

Usage: imperium [OPTIONS] <COMMAND>

Commands:
  ping        Check that imperium-core is running and measure a round trip
  chat        Chat with an agent in an environment or a project folder
  session     Manage sessions (also `sessions`)
  config      Inspect configuration
  mods        Install and update UI mods, asking you to approve the permissions they request
  secret      Manage secrets in the OS keychain (an encrypted file where there is none)
  models      Local models: the configured model folders, and downloads from Hugging Face
  memory      Your global memories. (An environment's notes are its Memory.md.)
  api         The OpenAI-compatible API other tools use your models through
  phone       Paired phones
  remote      Remote hosts over SSH
  daemon      The daemon itself
  env         Environments: named sets of folders sessions work in
  workspaces  Environments' working folders: each one's `Memory.md` and its sessions' scratch folders
  project     Project agents
  approvals   Requests from unattended work (such as auto-fix pushes) waiting for a yes or no
  schedule    Scheduled tasks the daemon runs
  workflow    Workflow packs and context retrieval
  pack        Policy pack updates: fetch a pack from a source you added, read what changed in plain words, and accept or reject it. Nothing is applied until you accept
  runtime     Inference runtimes
  mcp-serve   Serve the Claude harness: an MCP server on standard input and output that lets an external agent such as Claude Code start sessions, follow them and answer their permission requests through this daemon. Register it in `.mcp.json`. With `--tools` it serves Imperium's own tools instead (files, search, web, memory), each run in an Imperium session under the user's permission rules
  mcp         Remote MCP servers that use OAuth: sign in and out
  agents      Named agents: subagents defined by Markdown files that the root agent can delegate to
  run         Run one task through the real agent loop without the daemon or the desktop, against any OpenAI-compatible model endpoint, and print the result (transcript, plan, token and cost ledger, exit reason) as JSON: the harness evaluations run through. With `--print-prompt` it prints the resolved system prompt and tool schemas instead, without calling a model. Exit code 0 when the agent finished its turn, 3 when the run stopped early (a ceiling, the step limit, a timeout or a model error), 1 when it could not run
  resources   CPU, GPU, RAM, and VRAM usage, the local models loaded, and the endpoints sessions use
  help        Print this message or the help of the given subcommand(s)

Options:
      --remote <REMOTE>
          Talk to a remote daemon connected with `imperium remote connect`

  -h, --help
          Print help

  -V, --version
          Print version

===== imperium chat =====
Chat with an agent in an environment or a project folder

Usage: imperium chat [OPTIONS]

Options:
      --env <ENV>
          Environment (name or id) the agent works in: all its folders are open to it. With neither this nor --project, the session starts in the built-in Home environment

      --remote <REMOTE>
          Talk to a remote daemon connected with `imperium remote connect`

      --project <PROJECT>
          Project folder the agent works in (its environment, made if needed); `--project .` is the current directory

      --model <MODEL>
          Model as `<endpoint>:<model>` or a model table id; defaults to `models.default`

      --context
          After each turn, print one line on how full the model's context is (type /context for the full breakdown at any time)

      --worktree [<BRANCH>]
          Start on git worktrees: each folder in a git repository gets a new worktree on a new branch (`imperium/<session id>`, or the branch given)

      --subfolder <FOLDER>
          Narrow the session to one folder inside the environment's folders (absolute, or relative to its first folder): the only folder the agent can use

      --read-only
          Mount the session's folders read-only: the agent reads but never writes there, and commands run only under isolation.tier = os or container

  -h, --help
          Print help

===== imperium mods install =====
Install a mod from a git URL or a folder. Shows the permissions it requests and its content hash and asks before installing; nothing in the mod runs. Mods appear in the desktop app (Settings → Mods)

Usage: imperium mods install [OPTIONS] <SOURCE>

Arguments:
  <SOURCE>
          A git URL (`https://`, `ssh://`, `git@host:path`, `file://`) or a folder

Options:
      --path <PATH>
          The folder inside the source that holds the mod (its `mod.json`)

      --remote <REMOTE>
          Talk to a remote daemon connected with `imperium remote connect`

      --revision <REVISION>
          A branch, tag, or commit (git only)

      --sha256 <SHA256>
          Install only if the mod's content has this SHA-256 (as shown by a previous run)

  -y, --yes
          Approve without asking (for scripts)

  -h, --help
          Print help

===== imperium models =====
Local models: the configured model folders, and downloads from Hugging Face

Usage: imperium models [OPTIONS] <COMMAND>

Commands:
  local    List GGUF models in models.folders, whether each fits in memory, and what is loaded
  unload   Unload an idle local model now, freeing its memory
  files    List the quantisations a Hugging Face repository offers, with sizes and whether each fits this machine
  pull     Download a model from Hugging Face into models.download_dir, showing progress
  cancel   Stop a download; pulling the same model again resumes it
  folders  List, add, or remove model folders (models.folders); changes are scanned at once
  use      Make a model the default for new sessions (models.default)
  test     Load a model and send it one short prompt, showing the reply and its speed
  bench    Benchmark local models: load time, time to first token, prompt and generation speed, peak memory. Loads each model like any call does, waiting while the machine is saturated; saves the numbers per model and machine. Ctrl+C cancels
  help     Print this message or the help of the given subcommand(s)

Options:
      --remote <REMOTE>
          Talk to a remote daemon connected with `imperium remote connect`

  -h, --help
          Print help

===== imperium mcp-serve =====
Serve the Claude harness: an MCP server on standard input and output that lets an external agent such as Claude Code start sessions, follow them and answer their permission requests through this daemon. Register it in `.mcp.json`. With `--tools` it serves Imperium's own tools instead (files, search, web, memory), each run in an Imperium session under the user's permission rules

Usage: imperium mcp-serve [OPTIONS]

Options:
      --remote <REMOTE>
          Talk to a remote daemon connected with `imperium remote connect`

      --tools
          Serve Imperium's own tools to the caller instead of driving sessions

      --environment <ENVIRONMENT>
          With --tools: the environment (name or id) the tools work in; default Home

      --project-dir <PROJECT_DIR>
          With --tools: a folder to work in instead of an environment

      --session <SESSION>
          With --tools: run the calls in this existing session instead of starting one

      --model <MODEL>
          With --tools: the model of the session this starts (the tools never call it)

      --allow-write
          With --tools: also offer the tools that write files, run commands or save memory. Each still asks under the session's permission mode

      --approval-timeout-s <APPROVAL_TIMEOUT_S>
          With --tools: seconds a permission request waits for you before it is refused; 0 refuses at once (use it when nobody is watching)
          
          [default: 120]

  -h, --help
          Print help

===== imperium run =====
Run one task through the real agent loop without the daemon or the desktop, against any OpenAI-compatible model endpoint, and print the result (transcript, plan, token and cost ledger, exit reason) as JSON: the harness evaluations run through. With `--print-prompt` it prints the resolved system prompt and tool schemas instead, without calling a model. Exit code 0 when the agent finished its turn, 3 when the run stopped early (a ceiling, the step limit, a timeout or a model error), 1 when it could not run

Usage: imperium run [OPTIONS]

Options:
      --headless
          Run without the daemon or the desktop. Required to run a task (`--print-prompt` needs neither)

      --remote <REMOTE>
          Talk to a remote daemon connected with `imperium remote connect`

      --json
          Print the result as JSON. It is the only output format; scripts pass it to say so

      --print-prompt
          Print the resolved system prompt and tool schemas as JSON and stop, without calling a model. The prompt shows `{workspace}` where the working folder goes

      --task <TASK>
          The task: a JSON file with a `prompt` (its other fields are kept in the output), or the prompt itself

      --workspace <WORKSPACE>
          The folder the agent works in. Its tools can read and, where the permission mode lets them, change it: point it at a copy

      --root-model <ROOT_MODEL>
          The root model's endpoint: an OpenAI-compatible base URL such as `http://127.0.0.1:8080/v1`, optionally followed by `#<model id>`

      --model-id <MODEL_ID>
          The root model's id at that endpoint (when `--root-model` has no `#<id>`)

      --api-key-env <VAR>
          The environment variable that holds the endpoint's API key. The key is never printed

      --local
          The root model runs on this machine (a local llama-server): the harness aids that are `auto` count as on, as in the product, where `auto` means on for a local model

      --context-tokens <N>
          The root model's context window in tokens

      --effort <EFFORT>
          How hard a model that can reason thinks: low, medium, high or max

      --thinking <THINKING>
          Turn thinking on or off by sending `chat_template_kwargs.enable_thinking` (llama.cpp, vLLM)
          
          [possible values: on, off]

      --chat-template-kwargs <JSON>
          A JSON object sent as `chat_template_kwargs` with every request of the root model

      --variant <VARIANT>
          A named variant (`<config>/harness-variants/<name>.toml`) or the path of a variant file

      --prompt-overlay <FILE>
          A text file appended to the root agent's system prompt, after any variant's edits

      --flag <KEY=VALUE>
          A loop flag, `key=value`; repeatable. The flags are listed in docs/03-agent-engine.md: max_steps, effort, auto_compact, auto_compact_at, knowledge, attended, harness

      --subagent-replay <FILE>
          Answer subagents from this recordings file instead of running them (no model calls for subagents). A task file with a `subagent_replay` object is used when this is not given

      --cost-ceiling <USD>
          Stop before the next model call once this much has been spent, in US dollars. Needs prices (`--price-in` and `--price-out`)

      --token-ceiling <N>
          Stop before the next model call once this many tokens (prompt plus completion, over all agents) have been used

      --price-in <USD>
          Price of a million prompt tokens in US dollars, for the cost ledger

      --price-out <USD>
          Price of a million completion tokens in US dollars, for the cost ledger

      --permission-mode <PERMISSION_MODE>
          How the agent's tool calls are checked. A call that would ask is always denied: nobody answers. `full` runs everything the rules and the safety floor do not stop
          
          [default: default]

      --timeout-s <SECONDS>
          Stop the run after this many seconds
          
          [default: 1800]

      --journal <FILE>
          Keep the session's journal at this path (events, one JSON object per line)

  -h, --help
          Print help

===== imperium help run =====
Run one task through the real agent loop without the daemon or the desktop, against any OpenAI-compatible model endpoint, and print the result (transcript, plan, token and cost ledger, exit reason) as JSON: the harness evaluations run through. With `--print-prompt` it prints the resolved system prompt and tool schemas instead, without calling a model. Exit code 0 when the agent finished its turn, 3 when the run stopped early (a ceiling, the step limit, a timeout or a model error), 1 when it could not run

Usage: imperium help run
