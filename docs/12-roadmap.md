# 12 — Roadmap

Each phase ends with a usable build on all three desktop platforms. Exit criteria must be
demonstrated, not assumed.

"Merged" means the phase's code is on `main`; its exit criteria have so far been demonstrated
against fake model servers in tests and the browser preview, not yet against real hosted or
local models.

Implemented: **agent state management.** Agents and subagents from a session keep their state
(conversation context, plan, tool results, model, and usage), so a finished subagent becomes
idle and can be resumed with a follow-up and its earlier context instead of starting fresh,
for example handing more work to the subagent that already explored a module (`resume_agent`
for the root, `session.agent_resume`, `/resume-agent`, and *Continue with…* in the desktop's
Agents panel). Agent state is kept next to the session's files in the daemon's data folder
(`<id>.agents/`), so it survives daemon restarts and moves with the session; subagents a
restart cut off are marked interrupted and resumable
([03](03-agent-engine.md#agent-state)).

Implemented: **llama.cpp found, installed, and updated by itself.** The daemon finds
`llama-server` where package managers, LM Studio, and llama.cpp checkouts usually leave it,
prefers a build on the machine's own GPU backend and then the newest, and installs llama.cpp's
official build the first time a local model needs one when none usable is there (or only a CPU
build on a GPU machine). llama.cpp updates with Imperium: a newer pinned release replaces
Imperium's build lazily with one earlier build kept for rollback, package-manager installs get
an *Update* (or an automatic upgrade), and checkouts are never modified
([04](04-models-and-routing.md#llamacpp-updates)).

Implemented: **resource monitor.** A live view of what the machine and the sessions are using:
CPU, GPU, RAM, and VRAM usage, plus every active external endpoint and every local model in
use, including models still loaded or cached for active sessions (and which sessions use
them), in the desktop's Resources panel and `imperium resources [--watch]`
([04](04-models-and-routing.md#active-models-and-resource-monitor)).

Implemented: **the most context each local agent can use, reserved as it is used.** A local
model's agents may each use up to its ceiling: what the model was trained for, capped to what
fits in memory beside its weights (`context = "auto"`, the new default, or a number per model or
globally). The unified KV pool starts small and grows on demand by restarting the server between
calls, and starts small again after the model is unloaded, so VRAM is only reserved as context is
used; compaction is planned against the ceiling. Slots reserve nothing (16 by default), and the
pool also grows when agents fill it together. The weights stay on the GPU first, for each of
several models loaded at once: a KV pool that does not fit beside them is cut rather than moving
layers to the CPU. Calls say why they wait for a local model, and the model lists show the
loader's own memory plan ([04](04-models-and-routing.md#runtimes)). Not measured on hardware
yet: restoring saved slots into a grown pool, and llama.cpp's compute buffers at large contexts.
Next: shrinking a loaded pool after sustained low fill (today it shrinks on unload), growing a
squeezed pool once other models leave, fill read from llama-server's own metrics, and showing
the wait reason in the desktop.

Implemented: **multiple persistent agents per environment.** An environment holds zero or more
persistent agents, each with its own name, role, session and limits, created explicitly (a new
environment has none) with `environments.agent_create`, `imperium env agent add`, or *Add agent* in
the environment window; the earlier single persistent session migrates to one agent with its
history, and the old `persistent_agent` fields stay as aliases for protocol 0.22
([14](14-projects-and-automation.md#persistent-agents-implemented)). Per-agent permission
profiles (MCP and plugin allowlists, a local-files-only lock) and per-agent initiative follow.

## Next (in order)

1. **OS notifications** (implemented). System notifications for approvals, finished and failed
   turns, finished model downloads, and ready updates, with per-kind switches, a background-only
   default, and an internal `notify` entry point for budget alerts
   ([07](07-desktop-ui.md#notifications-implemented)).
2. **Permission rules** (implemented). Allow, ask, and deny rules per tool, command prefix, and
   path glob, globally and per environment (deny over ask over allow, environment rules
   overriding global ones of equal specificity), with *Always allow* on approvals; read-only or
   writable path grants outside environments (global package caches, toolchains) with per-OS
   presets, carried into the OS sandbox and container mounts
   ([05](05-tools-and-isolation.md#permissions), [07](07-desktop-ui.md#permissions-implemented)).
   Permission modes (ask every time, accept edits, plan only, full access) came with item 25.
3. **Budgets and alerts** (implemented). Daily, weekly, and monthly token and cost budgets
   globally, per environment, per endpoint, and per model (configurable week start and monthly
   reset day, local time), with usage persisted across restarts; alerts at configurable
   thresholds (default 50/80/100%) through notifications, and warn, ask before each new turn, or
   block new turns when used up; Settings → Budgets, a Usage dashboard, and a budget mark beside
   the context meter ([10](10-configuration.md#budgets), [07](07-desktop-ui.md#budgets-and-usage-implemented)).
4. **Command palette** (implemented). Ctrl+K (Cmd+K) in the main and panel windows: fuzzy
   search over actions, sessions (archived ones grouped), environments, models for the open
   session, panels, and settings sections, recently run first, from a typed command registry
   features register into; plus a light, dark, or system theme setting
   ([07](07-desktop-ui.md#command-palette-implemented)). Rebindable shortcuts remain to do.
5. **Attachments and voice** (implemented). Images, PDFs, and files attached to messages by
   paperclip, paste, or drop, as chips in the composer and the transcript: images as image parts
   for vision models (else a path), PDF text (and embedded page images for vision models), text
   inlined up to a limit with a truncation marker, other files as paths the agent reads; files
   from outside the session's folders copied into its attachments folder; journalled and counted
   in the context breakdown. Push-to-talk (a held key or the mic button) transcribes into the
   composer through `[media.transcription]`
   ([07](07-desktop-ui.md#attachments-and-voice-input-implemented)). Describing images for models
   without vision, rendering drawn PDF pages, and a supervised local whisper remain to do.
6. **Review pane and checkpoints** (implemented). Diffs of an agent's changes with
   accept or reject per hunk, then commit or open a pull request; git-based checkpoints to
   rewind a session's files and conversation. Checkpoints: before each root turn that changes
   files in a git repository, the session's files (tracked and untracked, not ignored) are kept
   as a commit on a private ref, `refs/imperium/checkpoints/<session>/<n>`, built with plumbing
   in a temporary index so the repository's index, HEAD, and branches are never touched, and
   linked to the journal and the saved conversation; `session.checkpoints` lists them and
   `session.rewind` (`/rewind`) puts the files back (undoable), forks the conversation at that
   point into a new session, or both. Folders outside git have none
   ([14](14-projects-and-automation.md#checkpoints-and-rewinding)). Review pane: the desktop's
   Review panel and `/diff` list the files the session's turns changed since a checkpoint (the
   session's start by default) as unified diffs computed by the daemon; each hunk or file is
   accepted (kept and hidden, on a private review ref) or rejected (reverted in the working
   tree), then *Commit* (message prefilled from the session's title; only the session's files,
   hooks off) and *Open pull request* (`gh`, or the commands to run), both gated by the
   `git_commit` and `open_pull_request` permission rules and asking by default
   ([14](14-projects-and-automation.md#review-pane-implemented),
   [07](07-desktop-ui.md#review-panel-implemented)).
7. **Branching and comparison** (implemented). Branch a conversation from any message; run
   best-of-N across models and compare the results side by side. `session.branch` copies a
   session's journal and root conversation up to a message into a new session
   (`branched_from`), optionally in a worktree of its own holding the files of that point;
   `session.compare` sends one message to two to four branches, one per model, run in parallel
   under the usual agent and residency limits and tagged with a shared `comparison_id`;
   `session.compare_pick` keeps one and archives the rest. The desktop has a "Branch from here"
   hover action, a compare form and side-by-side view, and nests branches under their source;
   `imperium chat` has `/branch`, `/compare` and `/pick`
   ([14](14-projects-and-automation.md#branching-and-comparison),
   [07](07-desktop-ui.md#branches-and-model-comparison-implemented)). Merging branches back
   together is not offered.
8. **Session search** (implemented). Session journals, running and archived, are indexed in the
   background (incrementally, within a per-pass budget) on the memory crate's retrieval layer:
   keyword ranking, fused with vector similarity when `memory.embedding_model` is set;
   `session.search` for clients, a search box in the Sessions panel that opens a session at the
   match, and the `search_sessions` tool, which reaches only the agent's own environment unless
   `memory.session_search_scope` is `all` ([17](17-memory.md#session-search-implemented),
   [07](07-desktop-ui.md#session-search-implemented)).
9. **Live preview and browser** (implemented). A Preview panel shows the page the project's dev
   server serves (an agent starts it with `preview_open`, a command and port run as a managed
   background process under the session's sandbox and permission rules, or shows a loopback
   URL; loopback pages only, enforced in the daemon, the panel, and the window's CSP), and the
   Browser panel lets the user take over the agent's browser (click, type, navigate, back,
   *Give back to agent*) while the agent's browser tools are refused
   ([05](05-tools-and-isolation.md#live-preview-implemented),
   [07](07-desktop-ui.md#preview-and-browser-panels-implemented)). Protocol 0.18.
10. **Local-model extras** (implemented). Speculative decoding with draft
    models, a local model benchmark, and an OpenAI-compatible local API server for other tools.
    Speculative decoding is implemented: a per-model `draft_model` (an installed, smaller GGUF
    with the same tokenizer family) with `draft_max`, `draft_min` and `draft_gpu_layers`, passed
    to llama-server's `--spec-draft-model` and `--spec-type draft-simple`; the draft counts in the
    model's memory plan and residency accounting, and a missing, incompatible or oversized draft
    loads the model without it and says why ([04](04-models-and-routing.md#speculative-decoding-implemented),
    [07](07-desktop-ui.md), [10](10-configuration.md)). Protocol 0.24. The API server is implemented:
    opt-in, loopback by default, with its own token in the secret store, `/v1/models` and
    `/v1/chat/completions` (streamed or not), calls that go through the residency controller
    and count toward budgets as the `api` source, hosted models only by explicit per-model
    opt-in, Settings → API and `imperium api`
    ([04](04-models-and-routing.md#openai-compatible-local-api-implemented),
    [07](07-desktop-ui.md#api-settings-implemented), [10](10-configuration.md)). The local
    model benchmark is implemented too: `models.bench` (Settings → Models, `imperium models
    bench [<id>]`) loads each chosen model through the normal residency path as a background
    call, never unasked and cancellable, and measures load time, time to first token, prompt and
    generation speed and peak memory from the real stream, saved per model, hardware fingerprint
    and date ([04](04-models-and-routing.md#local-model-benchmark-implemented),
    [07](07-desktop-ui.md#local-model-benchmark-implemented)). Protocol 0.21. Both parts
    are implemented, so item 10 is fully implemented.
11. **Sharing and sync (design)** (designed). Design plans for session sharing and export, and
    for team sync: a portable session bundle with shared redaction, a mandatory preview and
    read-only import with explicit forking, and team sync as a git-backed config layer that
    narrows automatically and widens only on review, in phases from shared redaction and
    settings export onward ([19](19-sharing-and-sync.md)). No code yet.
12. **Environment file access** (implemented; bug, from use of the app so far, like the items
    after it). Agents failed to read paths an environment grants them: an agent could not open
    the Imperium-AI checkout given as the environment's first project path. The folder checks
    held for exact spellings; the file tools now also read the spellings models write for a
    Windows path with spaces (quoted or padded, backslashes left unescaped in the JSON
    arguments, `file://`, Git Bash and WSL forms), each still checked against the folders and
    grants, and a session test lists and reads an environment's first folder whose path has
    spaces ([05](05-tools-and-isolation.md#isolation-tiers)).
13. **Worktrees by default** (implemented). An environment's sessions get its project-specific
    worktrees without extra setup: the git worktrees of its folders' repositories (main checkout
    and linked worktrees, including ones added while a session runs) are discovered from git's
    records, open with the same access and checks as the folders, and turned off with the
    environment's **Project worktrees** switch
    ([14](14-projects-and-automation.md#worktrees), [05](05-tools-and-isolation.md#isolation-tiers)).
14. **Visible tool calls** (implemented). The transcript shows each tool call, with arguments
    and result, for the session and for every subagent, collapsed by default: one line per call
    (state, tool, summary, run time) that opens to the arguments and result, long text behind
    "show more" ([07](07-desktop-ui.md#tool-calls-implemented)).
15. **Reasoning effort** (implemented). Models that can reason get a per-session effort
    setting (low, medium, high, max), mapped to each backend's reasoning controls and hidden
    for models without them: `models.effort` sets the default, `session.control` `set_effort`
    (and `/effort` in the CLI, a selector beside the model in the desktop app) changes it,
    `spawn_agent` may set one for a subagent, and whether a model reasons comes from its table
    row, its tags, a local model's chat template, or its name
    ([04](04-models-and-routing.md#reasoning-effort), [07](07-desktop-ui.md)).
16. **Memory control in core** (implemented). imperium-core's residency controller owns every
    decision about which models and KV caches are resident: a plan loop for idle unloads and
    settings restarts, the policy calls ask to make room, `models.unload`, resumes, and a
    memory budget refreshed from live readings. The local runtime only carries them out, and
    every move is reported with its reason (`model.residency`)
    ([04](04-models-and-routing.md#residency-controller-implemented)). The races the review
    found are fixed (titles never load a model, a crashed server is unloaded as `crashed` and
    reloaded with a backoff, a resuming agent waits for its own slot's save), and the desktop
    wait line and `imperium chat` show the moves. Still to do: measuring on real hardware.
17. **Session titles and list** (implemented). After a session's first exchange the core
    titles it in the background with a model that is cheap to ask now (the session's model
    when it is local and loaded with a free slot, another loaded local model, or the session's
    hosted model), never loading one for it; otherwise, and for background sessions, the title
    is the first message's first words. `session.control` `rename` sets a title the user
    keeps across restarts and no generated title replaces; session rows are one line (status
    dot, title, time since activity) with the rest in the tooltip, renamed by double-click or
    *Rename* in the row's menu ([07](07-desktop-ui.md#environments-and-sessions-implemented)).
18. **Quieter interface** (implemented). Panels carry too many buttons. Keep the primary action
    visible, move the rest into overflow menus or hover actions, and tighten spacing and type for
    a sleeker look: panel headers show the title, the primary action and one ⋯ menu (collapse
    all, detach, close, and the panel's secondary actions); row actions appear on hover or
    focus; header and title-bar actions are icon buttons with labels; control sizes and type
    steps are shared tokens ([07](07-desktop-ui.md#quiet-interface-implemented)).
19. **Emperor behaviour.** Train Emperor towards the working style of frontier agent models,
    and reinforce it in the system and root prompts:
    - concise, structured answers; the big picture first, more detail only when asked;
    - use tools and delegate rather than pasting code at the user;
    - few emojis, and plain explanations instead of many tables;
    - search for information rather than relying on what was learned in training.

    The prompt half is implemented: the engine's root and subagent prompts and
    `emperor-root.md` carry these rules, pinned by tests
    ([03](03-agent-engine.md#response-style)). Training Emperor on them remains.
20. **Free scroll while streaming** (implemented). Scrolling up while an agent is writing stops
    following the output and keeps the user's place; a *Jump to latest* button (and scrolling
    back to the bottom, or sending a message) resumes following the newest text, in the session
    transcript and in a subagent's log
    ([07](07-desktop-ui.md#free-scroll-while-streaming-implemented)).
21. **Model awareness for the root agent** (implemented). The root agent can list the local models it may
    use (only those visible to the session, with whether each fits in memory now). It can also
    retrieve, through the RAG layer, what each model is good at (coding, writing, research,
    and so on), from model cards and Imperium's own measurements. The root agent uses this to
    pick a model when it delegates
    ([04](04-models-and-routing.md#model-awareness-and-model-cards-implemented)).
22. **Agents manage the app config** (implemented). By default, and outside configured
    environment projects too, agents may add to the user's local app config: filling in model
    cards (`set_model_card`), and downloading and installing mods, plugins, and skills
    (`install_extension`, `uninstall_extension`) from a git URL or a local folder. Each change
    goes through the permission rules, so the user can narrow it to *ask* or *deny*, and is
    recorded in a change journal so it can be undone (Settings → *Changes by agents*,
    `imperium config changes` / `undo`). Installs show where they came from
    ([06](06-extensibility.md#agents-manage-the-app-config-implemented)).
23. **Lazy skills and plugins** (implemented). Only each skill's and plugin's name and short
    description are loaded up front. The rest is loaded when an agent first uses it, keeping
    context and start-up cost low: `load_skill` brings in a skill's instructions once per
    conversation, `activate_plugin` starts a plugin's MCP servers and offers their tools, both
    journalled so a resumed session restores them, and `extensions.eager` / `extensions.lazy`
    load chosen ones (or all) up front. Hooks stay active from the start, since a hook may be a
    security check that must see every call
    ([06](06-extensibility.md#lazy-skills-and-plugins-implemented)).
24. **Context and transcripts** (implemented). Each agent compacts its own conversation mid-turn
    when the next call would reach `context.auto_compact_at` of its window, keeping the system
    prompt and loaded workflow context verbatim
    ([03](03-agent-engine.md#context-management)). Transcripts, subagent task trees, and the
    files agents attached or made export as Markdown or JSON (`session.export`, `imperium
    session export`, and *Export* in a session's menu), for archived sessions too
    ([07](07-desktop-ui.md#exporting-transcripts-implemented)).
    Items 25–35 are described in the design docs and, unless marked implemented, not built yet
    (their *planned* and *later work* notes; each links to where it is described).
25. **More tools and permission modes** (implemented). `glob` and `grep` file tools that
    honour `.gitignore`, folder checks, and deny rules, with paged output
    ([05](05-tools-and-isolation.md#glob-and-grep-implemented)); background processes for
    `run_command` with `command_output` and `command_stop`, capped and buffered per session and
    killed with it ([05](05-tools-and-isolation.md#background-commands-implemented)); and
    per-session permission modes (`ask`, `default`, `accept_edits`, `plan`, `full`) under deny
    rules and a built-in safety floor, set by `permissions.mode`, `session.control`
    `set_permission_mode`, `/mode` in the CLI, and the session footer
    ([05](05-tools-and-isolation.md#permission-modes-implemented),
    [07](07-desktop-ui.md#environments-and-sessions-implemented)). Remote runtimes do not have
    the search tools or background commands yet.
26. **Worktrees for parallel writers** (implemented). A subagent started with
    `spawn_agent` `access: "write"` works in a git worktree of its own on its own branch, so
    concurrent edits never collide; its work comes back as a commit on that branch with a
    merge report, and the worktrees go with the session
    ([14](14-projects-and-automation.md#worktrees)). The planned `[worktrees]` settings and the
    Worktrees pane are not built.
27. **Environment configuration.** An environment's own `.imperium/config.toml` (instructions,
    policy, plugins, MCP servers, routing, budgets), sessions narrowed to a subfolder or a
    read-only mount, and schedules and project agents per environment
    ([14](14-projects-and-automation.md)).
28. **Local runtimes and hardware.** vLLM as a supervised runtime, GPU probes for AMD, Intel,
    and Apple Silicon, and memory estimates calibrated against measured use
    ([04](04-models-and-routing.md)).
29. **Routing extras.** Queue-delay handling, capability filters, escalation, and built-in
    rules sending critique, review, and verify tasks to the CPU lane
    ([04](04-models-and-routing.md)).
30. **Hooks and mods.** More hook events, hooks that rewrite calls, HTTP hooks; more mod
    contribution points, install and update commands, a permission prompt at install, and
    trusted main-context mods ([06](06-extensibility.md)).
31. **Policy packs and MCP.** Fetching pack updates shown as a diff to accept, a policy crate
    that layers packs into the prompt; MCP resources, prompts, sampling, and OAuth for remote
    servers; and an MCP server bridge exposing Imperium itself
    ([08](08-agent-policy.md), [05](05-tools-and-isolation.md#mcp), [02](02-architecture.md)).
32. **Web and browser.** More search providers (Kagi and others), caching and robots handling,
    browser tabs and downloads, and a browser pane the user can take over
    ([05](05-tools-and-isolation.md)).
33. **Protocol transport.** Event subscriptions, and Unix sockets and Windows named pipes for
    SSH forwarding ([02](02-architecture.md#protocol)).
34. **Desktop and platform gaps.** Rebindable shortcuts; attachments for models without
    vision (image descriptions), drawn PDF pages, and a supervised local whisper; an encrypted
    secret store where no keychain exists; WASM pet behaviours
    ([07](07-desktop-ui.md), [10](10-configuration.md), [16](16-pets.md)).
35. **Layouts.** Dragging panels out into windows and modules between panels, project layout

36. **Environment working folders** (implemented). Every environment gets a working folder under
    `workspaces.root` (default `<data>/workspaces`): a `Memory.md` of notes for that environment
    alone, read into its sessions' context like workflow context and never compacted, and a scratch
    folder per session, added as a writable grant, deleted when the session is archived and made
    again, empty, when it is unarchived. Changing the root moves the whole tree (rename, or copy
    and verify, with rollback), from Settings, `imperium workspaces move`, or `config set`
    ([14](14-projects-and-automation.md#environment-working-folders-implemented),
    [17](17-memory.md#environment-memory-implemented)). Orphan scratch folders are swept at
    start. Not built: tracking the background processes a session started in its scratch folder,
    which can keep a folder from being deleted or moved.

37. **Home environment** (implemented). A built-in *Home* environment exists without being
    created, is the default for a session started with no environment or project, has no
    project folders (each session works in its own scratch folder, with Home's `Memory.md`),
    reaches web-hosted files and the user's connectors under the normal permission modes, runs
    no persistent agent, and cannot be deleted
    ([14](14-projects-and-automation.md#home-implemented)).

38. **Agent initiative** (implemented). Persistent agents can look for work on their own, when the
    machine is quiet and the user is idle in the environment: per agent `off` (the default),
    `suggest` (a read-only review of the roadmap, plans, notes and sessions that yields a short
    list of suggested work with a source each, shown with one-click *Start*, plus a daily
    work-left reminder) or `act` (it may also start a few tagged background sessions itself,
    worded as the user would word them, in default permission mode and within per-agent daily and
    concurrent limits that also bind the follow-up turn after a report), with `initiative.*`,
    notifications, `imperium env agent …`, and `[initiative]` settings
    ([14](14-projects-and-automation.md#initiative-implemented),
    [10](10-configuration.md#initiative), [07](07-desktop-ui.md)). Open issues and pull
    requests are not read yet.

Custom agents come from customised open-weight models (Emperor and Consul) rather than a
separate agent builder, and checkpoints are git-based rather than a separate snapshot store.

Later candidates: fine-tuning plugin (Unsloth), shared team projects, a plugin registry.
