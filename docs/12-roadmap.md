# 12 — Roadmap

Each phase ends with a usable build on all three desktop platforms. Exit criteria must be
demonstrated, not assumed.

"Merged" means the phase's code is on `main`; its exit criteria have so far been demonstrated
against fake model servers in tests and the browser preview, not yet against real hosted or
local models.

| Phase | Theme | Scope | Exit criteria |
| ----- | ----- | ----- | ------------- |
| 0 | Foundations (done) | Workspace scaffold, protocol crate + TS export, config and keychain, CI green on all OSes | `imperiumd` starts, `imperium ping` round-trips; generated TS types checked in CI |
| 1 | Core agent (merged) | Agent loop, OpenAI-compatible endpoints, file and exec tools, permission prompts, session journal, CLI chat | A CLI session edits files in a project folder using a hosted model, with cost recorded |
| 2 | Desktop shell (merged) | Tauri app, tiling layout, scaling controls, conversation, telemetry pane | Ultrawide and 4K layouts verified; live tokens/sec and cost per call |
| 3 | Planning and delegation (merged) | Plan phase and plan tools, plan UI, `spawn_agent`/`await_tasks`, task tree UI, budgets, router v1 (rules + cost scoring) | Root plans, delegates steps to 3 subagents on different endpoints, and uses no tokens while waiting |
| 4 | Local models (merged) | Model folders, GGUF parsing, runtime packs, llama.cpp supervision, hardware probe, memory planner | Router reuses a loaded model or falls back to hosted when memory is short |
| 5 | Ecosystem and memory (merged) | MCP client, skills, hooks, Claude Code plugin compatibility, UI mod SDK, policy packs, the workflow contract with context retrieval, global and project memory (files, search, recall, write approval) | Third-party MCP server, skill, and UI mod work unmodified; default policy can be disabled; a memory saved in one project's session is recalled in a new session; a hosted root and a local subagent given the same role and task load the same workflow files |
| 6 | Projects and automation (merged) | Projects, project agents, schedules, daemon at login, GitHub events and auto-fix responders | A cron schedule runs while the window is closed and notifies on completion; a failing PR check is fixed and pushed after approval |
| 7 | Isolation and remote (merged) | OS sandbox tier, container tier, SSH hosts, vLLM (Linux/WSL2/remote) | Remote project runs on an SSH host's GPU from the local desktop |
| 8 | Web and browser (merged) | Web search providers, fetch, CDP browser tools | Agent researches and cites sources; browser pane mirrors agent actions |
| 9 | Pets (merged: engine, desktop panel; TUI and phone pending their clients) | Pet engine, pack format, renderers, importers | Pet reflects agent state in desktop, TUI, and phone |
| 10 | Media (merged: images, speech, transcription; sidecar and video later) | Media sidecar, ComfyUI integration, whisper.cpp, TTS | Image and audio generated by an agent, scheduled with LLMs by the memory planner |
| 11 | Mobile (first stage merged: pairing, scoped phone access, phone web app; native app, relay, and push later) | Phone app, pairing, relay, notifications | Paired phone approves a queued action away from the LAN |
| 1.0 | Release (in progress: sessions survive restarts; clients follow sessions started anywhere; desktop self-update on main and experimental channels) | Hardening, docs, signed installers, updater | [Success criteria](01-vision.md#success-criteria-for-10) met |

Planned: **task-scoped context.** Context loaded for one task is tagged with that task and
ejected from the conversation when the task finishes, saving context length. This covers
files read, tool results, retrieved workflow rules, and subagent reports. Only a short result
summary and the task's outcome stay behind, and the full material stays in the session
journal so it can be recalled if a later task needs it. Context the user pins, or that a later
plan step depends on, is kept. Small local models (such as the Emperor and Consul roots) gain
the most, since their effective context is the tightest.

Later candidates: fine-tuning plugin (Unsloth), shared team projects, a plugin registry.
