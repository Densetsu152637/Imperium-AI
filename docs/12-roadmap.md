# 12 — Roadmap

Each phase ends with a usable build on all three desktop platforms. Exit criteria must be
demonstrated, not assumed.

"Merged" means the phase's code is on `main`; its exit criteria have so far been demonstrated
against fake model servers in tests and the browser preview, not yet against real hosted or
local models.

Implemented: **agent state management.** Agents and subagents from a session keep their state
(conversation context, plan, tool results, model, and usage), so a finished subagent becomes
idle and can be resumed with a follow-up and its earlier context instead of starting fresh,
for example handing more work to the subagent that already explored a module (`resume_agent`
for the root, `session.agent_resume`, `/resume-agent`, and *Continue with…* in the desktop's
Agents panel). Agent state is kept next to the session's files in the daemon's data folder
(`<id>.agents/`), so it survives daemon restarts and moves with the session; subagents a
restart cut off are marked interrupted and resumable
([03](03-agent-engine.md#agent-state)).

Implemented: **llama.cpp found, installed, and updated by itself.** The daemon finds
`llama-server` where package managers, LM Studio, and llama.cpp checkouts usually leave it,
prefers a build on the machine's own GPU backend and then the newest, and installs llama.cpp's
official build the first time a local model needs one when none usable is there (or only a CPU
build on a GPU machine). llama.cpp updates with Imperium: a newer pinned release replaces
Imperium's build lazily with one earlier build kept for rollback, package-manager installs get
an *Update* (or an automatic upgrade), and checkouts are never modified
([04](04-models-and-routing.md#llamacpp-updates)).

Implemented: **resource monitor.** A live view of what the machine and the sessions are using:
CPU, GPU, RAM, and VRAM usage, plus every active external endpoint and every local model in
use, including models still loaded or cached for active sessions (and which sessions use
them), in the desktop's Resources panel and `imperium resources [--watch]`
([04](04-models-and-routing.md#active-models-and-resource-monitor)).

Implemented: **the most context each local agent can use, reserved as it is used.** A local
model's agents may each use up to its ceiling: what the model was trained for, capped to what
fits in memory beside its weights (`context = "auto"`, the new default, or a number per model or
globally). The unified KV pool starts small and grows on demand by restarting the server between
calls, and starts small again after the model is unloaded, so VRAM is only reserved as context is
used; compaction is planned against the ceiling. Slots reserve nothing (16 by default), and the
pool also grows when agents fill it together. The weights stay on the GPU first, for each of
several models loaded at once: a KV pool that does not fit beside them is cut rather than moving
layers to the CPU. Calls say why they wait for a local model, and the model lists show the
loader's own memory plan ([04](04-models-and-routing.md#runtimes)). Not measured on hardware
yet: restoring saved slots into a grown pool, and llama.cpp's compute buffers at large contexts.
Next: shrinking a loaded pool after sustained low fill (today it shrinks on unload), growing a
squeezed pool once other models leave, fill read from llama-server's own metrics, and showing
the wait reason in the desktop.

## Next (in order)

1. **OS notifications** (implemented). System notifications for approvals, finished and failed
   turns, finished model downloads, and ready updates, with per-kind switches, a background-only
   default, and an internal `notify` entry point for budget alerts
   ([07](07-desktop-ui.md#notifications-implemented)).
2. **Permission rules** (implemented). Allow, ask, and deny rules per tool, command prefix, and
   path glob, globally and per environment (deny over ask over allow, environment rules
   overriding global ones of equal specificity), with *Always allow* on approvals; read-only or
   writable path grants outside environments (global package caches, toolchains) with per-OS
   presets, carried into the OS sandbox and container mounts
   ([05](05-tools-and-isolation.md#permissions), [07](07-desktop-ui.md#permissions-implemented)).
   Permission modes (ask every time, accept edits, plan only, full access) remain to do.
3. **Budgets and alerts** (implemented). Daily, weekly, and monthly token and cost budgets
   globally, per environment, per endpoint, and per model (configurable week start and monthly
   reset day, local time), with usage persisted across restarts; alerts at configurable
   thresholds (default 50/80/100%) through notifications, and warn, ask before each new turn, or
   block new turns when used up; Settings → Budgets, a Usage dashboard, and a budget mark beside
   the context meter ([10](10-configuration.md#budgets), [07](07-desktop-ui.md#budgets-and-usage-implemented)).
4. **Command palette** (implemented). Ctrl+K (Cmd+K) in the main and panel windows: fuzzy
   search over actions, sessions (archived ones grouped), environments, models for the open
   session, panels, and settings sections, recently run first, from a typed command registry
   features register into; plus a light, dark, or system theme setting
   ([07](07-desktop-ui.md#command-palette-implemented)). Rebindable shortcuts remain to do.
5. **Attachments and voice.** Images, PDFs, and files in messages; push-to-talk voice input
   through the transcription layer.
6. **Review pane and checkpoints.** Diffs of an agent's changes with accept or reject per hunk,
   then commit or open a pull request; git-based checkpoints to rewind a session's files and
   conversation.
7. **Branching and comparison.** Branch a conversation from any message; run best-of-N across
   models and compare the results side by side.
8. **Session search** (implemented). Session journals, running and archived, are indexed in the
   background (incrementally, within a per-pass budget) on the memory crate's retrieval layer:
   keyword ranking, fused with vector similarity when `memory.embedding_model` is set;
   `session.search` for clients, a search box in the Sessions panel that opens a session at the
   match, and the `search_sessions` tool, which reaches only the agent's own environment unless
   `memory.session_search_scope` is `all` ([17](17-memory.md#session-search-implemented),
   [07](07-desktop-ui.md#session-search-implemented)).
9. **Live preview and browser.** A live preview of the app being built and an integrated
   browser the user drives, beside the agent's own browser view.
10. **Local-model extras.** Speculative decoding with draft models, a local model benchmark,
    and an OpenAI-compatible local API server for other tools.
11. **Sharing and sync (design).** Design plans for session sharing and export, and for team
    sync.
12. **Environment file access** (bug, from use of the app so far, like the items after it). Agents fail to read paths an environment grants them:
    an agent could not open the Imperium-AI checkout given as the environment's first project
    path. Start from `list_dir` and the path checks behind it (environment roots, path
    normalisation on Windows, the sandbox grant), then add a test that every project path is
    readable from inside the environment.
13. **Worktrees by default.** An environment's sessions get its project-specific worktrees
    without extra setup.
14. **Visible tool calls.** The transcript shows each tool call, with arguments and result, for
    the session and for every subagent, collapsed by default.
15. **Reasoning effort.** Models that can reason get a per-session effort setting (low,
    medium, high, max), mapped to each backend's reasoning controls and hidden for models
    without them.
16. **Memory control in core.** Review loading and unloading end to end: imperium-core
    should own every decision about which models and KV caches are resident, loaded, or
    unloaded (the local runtime only carries them out), with the reason for each move visible.
    The KV-residency work and the GPU rule are the starting point; measure on real hardware.
17. **Session titles and list.** Titles are generated automatically from the first exchange
    and can be renamed; session rows are compact, one line, as in the Claude interface.
18. **Quieter interface.** Panels carry too many buttons. Keep the primary action visible,
    move the rest into overflow menus or hover actions, and tighten spacing and type for a
    sleeker look.
19. **Emperor behaviour.** Train Emperor towards the working style of frontier agent models,
    and reinforce it in the system and root prompts:
    - concise, structured answers; the big picture first, more detail only when asked;
    - use tools and delegate rather than pasting code at the user;
    - few emojis, and plain explanations instead of many tables;
    - search for information rather than relying on what was learned in training.
20. **Free scroll while streaming.** Scrolling up while an agent is writing stops following
    the output and keeps the user's place; a *Jump to latest* button (and scrolling back to
    the bottom) resumes following the newest text.
21. **Model awareness for the root agent.** The root agent can list the local models it may
    use (only those visible to the session, with whether each fits in memory now). It can also
    retrieve, through the RAG layer, what each model is good at (coding, writing, research,
    and so on), from model cards and Imperium's own measurements. The root agent uses this to
    pick a model when it delegates.

Custom agents come from customised open-weight models (Emperor and Consul) rather than a
separate agent builder, and checkpoints are git-based rather than a separate snapshot store.

Later candidates: fine-tuning plugin (Unsloth), shared team projects, a plugin registry.
